# CSS 아키텍처

## 왜 이렇게 나눴나

시안(`C:\project-oil\{포털, 대시보드}`)은 화면마다 `<style>` 블록을 갖고, 그 안에 `:root`
토큰 정의를 통째로 복사해 두었다. 60여 개 화면에 같은 색이 60벌 있는 상태다. 색 하나를
바꾸려면 60곳을 고쳐야 하고, 실제로는 화면마다 값이 조금씩 어긋나 있다.

그래서 **스타일은 공통 파일에만 둔다**. 페이지·JSP 안의 `<style>` 블록과 인라인 `style=`
속성은 금지다(CLAUDE.md 절대 규칙 4). 이 규칙은 `ProjectConventionTest` 가 빌드마다 검사한다.

## 파일 구성과 로드 순서

```
static/css/
├── tokens.css       색·간격·타이포·치수. 색상 리터럴이 존재하는 유일한 파일
├── base.css         리셋 · 타이포그래피 · 폼 · 표 · 접근성 기반(포커스 링, 건너뛰기 링크)
├── layout.css       앱 셸 (헤더 · 좌측 메뉴 · 본문 · 푸터)
├── components.css   화면 공통 부품 (버튼 · 배지 · 카드 · KPI · 표 · 모달 · 팝오버 · 토스트)
├── portlet.css      위젯 대시보드 (그리드 · 박스 · 이동 모드 · 팔레트)
└── pages/<페이지키>.css   그 화면에서만 쓰는 배치
```

로드 순서는 **위에서 아래**다. 뒤에 오는 파일이 앞을 덮으므로 순서를 바꾸면 토큰이
무력화된다. `layout/shell-top.jspf` 가 이 순서로 넣는다.

페이지 CSS 는 JSP 상단에서 이름만 지정한다.

```jsp
<c:set var="pageCss" value="price-intl" />
<c:set var="usePortlet" value="true" />
<%@ include file="/WEB-INF/jsp/layout/shell-top.jspf" %>
```

## 색은 tokens.css 에만

`#rrggbb`, `rgb()`, `hsl()` 리터럴은 `tokens.css` 밖에 쓰지 않는다. 다른 파일은 전부
`var(--토큰)` 으로 참조한다. 값의 근거(명도 대비 실측)는 `접근성-색상-감사.md` 에 있다.

예외는 `rgba(...)` 로 쓰는 반투명 그림자·오버레이 하나뿐이다. 투명도가 섞인 값은 토큰화
이득이 적고 색 자체를 전달하지도 않는다.

### 텍스트 색과 채움 색을 나눈다

브랜드 앰버 `--am`(#f59e0b)은 흰 배경에서 2.15:1 이라 텍스트로 쓸 수 없다. 그래서
**채움·아이콘·장식은 원래 값, 텍스트는 어둡게 파생한 `-ink`** 로 나눴다.

| 용도 | 토큰 |
|---|---|
| 채움·아이콘 | `--am` `--cy` `--em` `--bl` `--rd` `--pu` |
| 텍스트 | `--am-ink` `--cy-ink` `--em-ink` `--bl-ink` `--rd-ink` `--pu-ink` |
| 연한 배경 | `--am-bg` `--cy-bg` `--em-bg` `--bl-bg` `--rd-bg` `--pu-bg` |

배지는 `--*-bg` + `--*-ink` 를 짝지어 쓴다.

### 경계선은 두 종류

| 토큰 | 용도 |
|---|---|
| `--bd` `--bd2` | 순수 장식 구분선. 대비 요건 없음 |
| `--bd-ui` | 입력·버튼·체크박스 등 **컴포넌트 경계**. WCAG 1.4.11 의 3:1 대상 |

섞어 쓰면 접근성 심사에서 걸린다. 폼 컨트롤에 `--bd` 를 쓰지 말 것.

### 위계는 크기와 굵기로

`--tx3`(#94a0ab, 2.67:1)은 폐기했다. 밝은 배경에서 4.5:1 을 만족하는 "아주 흐린 회색"은
존재하지 않는다. 대비를 낮춰 위계를 만들지 말고 `--fs-*` 와 `--fw-*` 를 쓴다.
하위 호환을 위해 `--tx3: var(--tx2)` 로 연결해 두었으나 신규 코드에서는 쓰지 않는다.

## 이름 규칙

블록 단위로 접두사를 붙이고, 자식은 `__`, 변형은 `--` 를 쓴다.

```css
.card { }             /* 블록 */
.card__title { }      /* 자식 */
.btn--primary { }     /* 변형 */
.is-nav-collapsed { } /* 상태 (JS 가 토글) */
```

상태 클래스는 `is-` 로 시작한다. 스타일 훅과 상태 훅을 이름으로 구분해 두면, JS 가 무엇을
건드리는지 CSS 만 보고도 알 수 있다.

## 접근성과 얽힌 부분

| 요건 | 어디서 처리하나 |
|---|---|
| 전역 포커스 링 | `base.css` 의 `:focus-visible`. `outline: none` 단독 금지 |
| 건너뛰기 링크 | `base.css` 의 `.skip-link` + `shell-top.jspf` 의 마크업 |
| 최소 터치 타깃 24px | `base.css` 의 `button`, 입력 `min-height` |
| 확대 시 가로 스크롤 금지 | 고정폭 대신 `minmax(0, 1fr)`. 포틀릿 그리드가 대표 사례 |
| 색만으로 정보 전달 금지 | `.kpi__delta--up/down` 의 ▲▼, `.badge` 의 문구, `.sb-item[aria-current]` 의 막대 |
| 애니메이션 최소화 | `tokens.css` 의 `prefers-reduced-motion` → `--motion: 0ms` |
| 고대비 모드 | `tokens.css` 의 `prefers-contrast: more` |

## JS 가 스타일을 건드릴 때

인라인 `style=` 금지는 **작성한 마크업**에 대한 규칙이다. 그렇더라도 스크립트가 좌표를
계산해 `element.style` 에 써 넣는 방식은 되도록 피한다. 스크롤·리사이즈마다 다시 계산해야
하고, CSS 만 읽어서는 최종 모습을 알 수 없기 때문이다.

이 프로젝트에서 실제로 피해 간 두 곳:

- **헤더 팝오버** — 트리거 버튼과 같은 `.hd__action`(position: relative) 안에 두어
  CSS 만으로 위치를 잡는다.
- **위젯 배치** — 박스가 자기 좌표를 `data-col` / `data-row` 속성으로 들고 있고,
  `portlet.css` 의 `.pt-grid > [data-col="0"] { grid-column-start: 1 }` 같은 규칙이 배치한다.
  자유 배치(드래그로 아무 칸에나 이동)를 지원하면서도 스크립트가 style 속성을 건드리지 않는다.
  행 수만큼 규칙이 필요해 다소 장황하지만(0~39행), 배치 규칙이 CSS 한곳에 모여 읽기 쉽다.
  드래그 중의 미리보기 상자도 같은 규칙을 써서 결과가 어긋나지 않는다.

## 새 화면을 추가할 때

1. 공통 부품으로 되는지 먼저 본다. `components.css` 에 있으면 그대로 쓴다.
2. 없으면 **`components.css` 에 추가**한다. 다른 화면에서도 쓸 모양이면 페이지 CSS 가 아니다.
3. 그 화면에서만 쓰는 배치만 `pages/<페이지키>.css` 에 둔다.
4. 색이 필요하면 `tokens.css` 에 토큰을 추가하고 `docs/접근성-색상-감사.md` 의 표를 갱신한다.
   `python docs/tools/contrast.py` 로 재측정한다.

## 자동 검사

`ProjectConventionTest` 가 빌드마다 확인한다.

- JSP 에 `<style>` 블록·인라인 `style=` 속성이 없을 것
- `tokens.css` 밖에 색상 리터럴이 없을 것
- `outline: none` 이 대체 표시 없이 쓰이지 않을 것
- 모든 화면 JSP 에 건너뛰기 링크가 있을 것
